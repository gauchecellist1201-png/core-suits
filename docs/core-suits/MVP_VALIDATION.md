# MVP Validation — 5店舗デモの進め方

## 合格の定義

「面白いですね」ではなく **「これ、うちで使いたいです」** と言わせること。
より厳密には、**デモの場で「いつから使えますか」または「いくらですか」を先方から聞かれる**こと。

## デモ前にやること（店舗ごと・所要 20分）

1. その店の**生地を5点**登録する（事前に写真をもらうか、訪問時に撮る）
2. その店の**顧客を1名**、架空で作る（実在のお客様は使わない）
   - 顧客写真は**その場で店主本人を撮らせてもらう**のがいちばん効く
3. その店のノウハウを1つ、店主に聞いて登録する
4. その場で試着を1枚だけ生成しておく（回線を確認する）

デモ用の店舗は `npm run seed` で作れる（銀座テーラー髙木・顧客4名・生地10点）。ただし**本番の説得力は「その店の生地」で出る**ので、可能なら現物を撮る。

## デモの流れ（15分）

| 分 | やること | 見せたいこと |
|---|---|---|
| 0–2 | 顧客ページを開く | 「お客様1人が1画面に収まる」 |
| 2–4 | その店の生地を選んで生成 | 10〜20秒で出る。**顔が変わっていない** |
| 4–6 | 別の生地でもう1枚 → Look 比較 | 「この生地でも見せて」がその場でできる |
| 6–9 | **AI スタイリスト** | 「前回ネイビーをお買い上げなので、今回はチャコールを」← ここで表情が変わる |
| 9–11 | 共有リンクを店主のスマホに送る | LINE に貼れる。お客様側の見え方 |
| 11–13 | **ダッシュボードの再来店の機会** | 「8ヶ月前のお客様が勝手に並ぶ」← ここが本命 |
| 13–15 | 分析（ROAI） | 「AI をいくら使って、いくら売れたか」 |

**6分の時点と11分の時点が山。** 画像生成は入口で、売りは後半にあることを体で分からせる。

## 聞くこと（デモ後）

必ずこの順で聞く。

1. 「いま、生地帳は何冊ありますか」→ 生地登録の負担が見える
2. 「お客様の連絡先はどこに残していますか」→ CRM の刺さり方が分かる
3. 「前に買ったお客様に、こちらから声をかけていますか」→ **ここで詰まる店ほど買う**
4. 「スタッフさんによって提案は変わりますか」→ ノウハウ機能の刺さり方
5. 「月 ¥29,800 で、月に1着多く売れると思いますか」→ 価格の反応

## 記録すること（店舗ごと）

| 項目 | |
|---|---|
| 店舗名・店舗数・スタッフ数 | |
| 生地の点数 | |
| 顧客データの持ち方 | 紙 / エクセル / POS / 頭の中 |
| 再来店の声かけ | している / していない |
| いちばん反応した画面 | 試着 / スタイリスト / 再来店 / 分析 |
| 反応した言葉 | そのまま書き取る |
| 価格の反応 | 高い / 妥当 / 安い |
| 断り文句 | そのまま書き取る |
| 「使いたい」と言ったか | Yes / No |

## 判断基準（5店舗が終わったあと）

| 結果 | 次の一手 |
|---|---|
| **3店舗以上が「使いたい」** | そのまま有料で開始。Phase 4（追客の自動下書き）へ |
| **1〜2店舗** | 反応した画面だけを深掘り。刺さらなかった機能は捨てる |
| **0店舗、ただし試着には反応** | 業種を疑う（スーツではなくブライダル・振袖・眼鏡かもしれない） |
| **0店舗、試着にも反応しない** | 撤退。CORE の他の事業に時間を戻す |

## デモで絶対にしてはいけないこと

- **お客様の実在の写真を使う。** 必ず店主本人か架空の人物で
- 「AI が全部やってくれます」と言う。**スタッフの道具**として売る
- 生成の失敗を隠す。失敗したら「今のは失敗です、もう一度」と言う。ここで嘘をつくと全部が嘘になる
- 完成イメージを「実物と同じ」と言う。**必ず現物確認をお願いする**と言い切る
- 見込み数字を見せる。画面に出るのは台帳に入った実額だけ

## 事前チェック（訪問の朝）

```bash
npm run check          # 型・テスト・恒久検査
npm run build          # 本番ビルドが通るか
```

- 生成が動くか（1枚だけ試す）
- 店舗の Wi-Fi が使えるか。**使えない前提でテザリングを用意する**
- 今月の残り回数（画面左下）が足りているか
