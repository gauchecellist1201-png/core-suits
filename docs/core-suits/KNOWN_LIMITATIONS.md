# Known Limitations

MVP の時点で分かっている限界。デモの前に必ず読む。

## AI 生成

1. **細かい柄の間隔が完全には一致しない。** ピンストライプ・シャドーストライプで間隔がずれることがある
2. **強い光沢（モヘア混など）の再現が弱い。**
3. **生地写真が無い生地では色柄が別物になる。** 画面に赤字で「生地画像なし」と出るが、生成自体は止めていない
4. **横向き・後ろ向き・複数人が写った写真では品質が落ちる。** 正面・上半身以上・明るい場所が前提
5. **失敗することがある。** 安全フィルタに当たると生成されない。そのときは日本語で理由を出し、回数は消費しない（原価は記録する）
6. **生成に 10〜20 秒かかる。** 画面は待つだけ。進捗の割合は出せない

## データ

7. **ローカル保管は1台のブラウザ・1つのサーバーでしか使えない。** 実店舗で複数端末から使うには Supabase が必要
8. **`npm run seed` は Supabase 環境では動かない。** 実店舗の台帳に架空の顧客を混ぜないための意図的な制限
9. **顧客の削除機能が無い。** 個人情報保護の観点で Phase 4 までに必ず入れる（現状はデータベースを直接操作するしかない）
10. **監査ログが無い。** 誰がいつどの顧客を見たかが残らない。複数店舗になる前に必要

## 機能

11. **LINE への自動送信は無い。** 共有リンクを手でコピーして貼る
12. **顧客写真の色補正が無い。** 撮影条件が揃っていない生地写真は、そのまま色がずれる
13. **採寸データを持っていない。** 「サイズはいつもの」ができない
14. **試着の生成中に画面を閉じると結果を見失う。** 生成自体は完了して顧客ページの履歴に残るが、スタジオ画面には出ない
15. **共有リンクを取り消す画面が無い。** データ構造（`revoked`）はあるが UI が無い
16. **顧客・生地の編集画面が限定的。** 登録後に直せるのはメモ・在庫・価格・主写真など一部だけ

## 運用

17. **総当たり防止がメモリ保持。** サーバーが複数台になると完全ではない（素の総当たりは止まる）
18. **AI 原価は推定。** 実際の請求と月初に突き合わせる必要がある（[UNIT_ECONOMICS.md](./UNIT_ECONOMICS.md)）
19. **為替を手で更新する必要がある。** `SUITS_USD_JPY`
20. **料金表を手で更新する必要がある。** 各社の値上げに追従しない

## セキュリティ

21. **RLS に policy を1つも作らない方式。** service role でしかアクセスできない。将来 Supabase Auth に寄せるなら書き換えが必要
22. **画像に EXIF が残る。** 位置情報を含む写真をそのまま保管している。Phase 4 までに除去する
23. **共有リンクは URL を知っていれば誰でも見られる。** パスワードは付いていない（期限14日のみ）。お客様が転送すると第三者も見られる
