# Competitive Moat

## 問い

「ChatGPT に写真と生地の写真を貼れば同じことができるのでは？」

**画像1枚だけを比べるなら、その通り。** ここを誤魔化さないところから始める。

## 要素ごとの正直な評価

| 要素 | Moat になるか | 理由 |
|---|---|---|
| 画像生成の品質 | **ならない** | 使っているのは他社の API。誰でも同じものが使える |
| プロンプト設計 | **ほぼならない** | 数ヶ月で追いつかれる。ただし「今の3ヶ月」は稼げる |
| 生地データベース | **なる（弱〜中）** | 作るのに時間がかかる。ただし店が自分で作ったものなので、店は持ち出せる |
| 顧客 CRM + 購入履歴 | **なる（強）** | 時間でしか作れない。使うほど厚くなる |
| 店舗ノウハウ | **なる（強）** | その店にしか存在しない。言語化した瞬間から資産になる |
| 追客エンジン | **なる（中）** | 仕組みではなく「習慣」になったときに強い |
| LINE 連携 | **ならない（単体では）** | 誰でも繋げる。CRM と繋がって初めて意味が出る |
| ROAI 計測 | **なる（中）** | 解約されにくくする。「効いている証拠」が画面にある |

## なぜ ChatGPT では代わりにならないか（4つ）

### 1. 在庫を知らない

ChatGPT は「チャコールのヘリンボーンが似合います」と言える。だがその店に**在庫があるか**は知らない。店頭で「それは今ありません」は最悪の接客になる。

CORE Suits は在庫切れを −40 点、取り扱い終了を −100 点にして候補から消す。**その店に実際にある生地しか勧めない。**

### 2. お客様が何を持っているか知らない

オーダースーツの2着目以降は「持っていないもの」を売る商売。ネイビーを持っている人にネイビーを勧めるのは、いちばんやってはいけない提案。

CORE Suits は購入履歴から色の系統を引き、同系色を −18 点、重ならない色を +10 点にする。**汎用 AI にこの情報は無い。**

### 3. 生地の実物を見ていない

「チャコールのヘリンボーン」と書くだけでは、AI は毎回違う色・違う柄の大きさを作る。CORE Suits はその店が撮った実物写真を毎回渡し、画像を言葉より優先させる。[FABRIC_ACCURACY.md](./FABRIC_ACCURACY.md)

### 4. 半年後に思い出さない

いちばん大きい差はここ。ChatGPT の会話は流れて消える。CORE Suits は8ヶ月前にネイビーを買ったお客様を**勝手にダッシュボードに並べる**。

売上は「試着の瞬間」ではなく「思い出した瞬間」に生まれる。

## 本当の Moat は3つだけ

### (a) データの厚み（時間でしか作れない）

顧客300名 × 購入履歴 × 好み × 試着履歴。これは1年使った店にしか無い。**乗り換えるほど損をする**構造になる。

### (b) 業務に入り込んだこと（習慣）

顧客登録・生地登録・成約記録が日々の業務になると、抜くのが痛くなる。CORE の他プロダクトと同じ Operating Layer の考え方。

### (c) 接客ノウハウの言語化（他店には無い）

「40代以上の経営者はプレミアム帯が通りやすい」は、その店のトップ販売員の頭の中にしか無い。それを登録して提案の順番に効かせた瞬間、**新人が同じ提案をできる**ようになる。

Phase 6 で、成約データからノウハウを自動で見つけるところまで行けば、**使うほど賢くなるのは自分の店の分だけ**という構造になる。これが最終的な Moat。

## 弱いところ（認めておく）

1. **生地データベースは店のもの。** 持ち出して他社に移れる。囲い込みには使えない
2. **試着画像だけなら1年以内にコモディティ化する。** 単体では売り物にならなくなる前提で設計している
3. **画像生成の会社に依存している。** 値上げ・提供終了のリスクがある → だから `ImageProvider` を差し替え可能にしてある
4. **LINE 連携は差別化にならない。** CRM と繋がって「誰に何を送るか」が自動で決まるところに意味がある
5. **店舗が入力しないと何も貯まらない。** 入力を義務にしないための工夫（名前だけで登録可・成約記録は1画面）が、そのまま製品の生死を決める

## 結論

CORE Suits の堀は「AI が上手いこと」ではない。

> **その店のデータに AI を接続したこと。**

だから Virtual Try-On 単体のサービスにはしない。試着は入口であって商品ではない。
