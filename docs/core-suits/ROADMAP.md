# Roadmap

## Phase 1 — Virtual Try-On MVP ✅ 完了

顧客写真 × 店の生地 → 完成イメージ。プロバイダ差し替え可能・原価記録つき。

## Phase 2 — AI Stylist ✅ 完了（MVP に含む）

在庫・季節・用途・好み・体型・購入履歴・店舗ノウハウで採点し、上位3案を理由つきで。自由入力にも対応。

**次の一手:** 生地写真の色補正（グレーカード基準）。撮影条件のばらつきを吸収する。

## Phase 3 — CRM ✅ 完了（MVP に含む）

顧客18項目・写真複数枚・購入履歴・試着履歴・提案履歴・接客メモ。

**次の一手:** 採寸データ（首・肩・胸・胴・袖丈・股下）。既存顧客の再注文が「サイズはいつもの」で終わる。

## Phase 4 — Follow-up Engine 🔨 半分

いま: 6ヶ月経過した顧客をダッシュボードに並べる。追客の状態（未対応 / 連絡済 / 成約 / 見送り）を持つ。

**残り:**
- 「提案をつくる」を押したら、その顧客の写真で3案を**自動生成して**下書きにする
- 送付文の下書き（お客様の名前・前回の購入・季節を入れた日本語）
- 通知（朝、今日声をかける人を1通のメールで）

## Phase 5 — LINE Integration

- LINE 公式アカウントと顧客をひもづける（接続コード方式。soma で実績あり）
- 共有リンクではなく LINE のトーク上で完成イメージを送る
- 返信を顧客ページに残す
- **配信は必ず人が押す。** 自動送信はしない（オーダースーツの単価で自動配信は信頼を壊す）

## Phase 6 — Sales Knowledge AI

いま: ノウハウを手で登録し、条件が合ったときに +12 点。

**次:**
- 成約データからノウハウを**見つける**（「この店では40代にグレンチェックの成約率が高い」）
- 見つけたものは必ず**人が承認してから**効かせる（勝手に学習して勝手に変わるのは店にとって怖い）
- 新人スタッフ向けに「この人にはこう説明する」の台本を出す

ここが最終的な Moat。→ [COMPETITIVE_MOAT.md](./COMPETITIVE_MOAT.md)

## Phase 7 — Multi-store

データ構造は対応済み（`organization_id`）。必要なのは
- 店舗をまたぐ集計画面
- 店舗ごとの生地在庫（同じブランドでも店で在庫が違う）
- 本部が全店のノウハウを見る画面

## Phase 8 — Fashion Sales OS

商材依存は `Fabric` / `GarmentSpec` / `tryOnPrompt.ts` の3つだけ。

```
CORE Suits（スーツ）
  → CORE Fashion（シャツ・靴・宝飾・アイウェア）
    → Retail AI Sales OS（百貨店・セレクトショップ）
```

`Customer` / `Purchase` / `FollowUp` / `SalesKnowledge` / `AiJob` / `Store` はそのまま使い回せる。

## 直近3ヶ月でやらないこと（意図的に）

| やらない | 理由 |
|---|---|
| 自社の画像生成モデル | 原価も品質も他社の API が上。作る理由がない |
| 3D 採寸・体型スキャン | 単価に見合わない。店の巻尺のほうが速い |
| 顧客向けアプリ | 主役はスタッフ。お客様に操作させない |
| 決済 | 既存の受注システムがある店が多い |
| 予約管理 | 既存ツールがある |
